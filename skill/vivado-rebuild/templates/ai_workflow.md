# 大模型协作提示词工作流（人工审核后执行）

> 此处为**可复用模板**，不是历史聊天原文。提交比赛协作记录时，应另外提供真实提示词、模型回答和修改日志。

## Prompt A：依赖检查

我正在整理一个 Vivado <版本> 工程用于 Tcl 可复现构建。下面是现有 Block Design 的 cell/VLNV 清单、源文件清单、自定义 IP Repo 路径、XDC 文件和部分 Tcl。请在**不改变硬件逻辑**的前提下，列出可能阻碍异机重建的依赖：外部绝对路径、缺失 IP、模块引用 RTL、版本和器件不匹配。请将“已证实”“推测”“需要人工验证”分别标明，并给出可用 Tcl Console 验证的命令。不要凭空补写 AXI 连接或 PS MIO 配置。

## Prompt B：诊断失败

执行 `<Vivado Tcl command>` 时出现以下**完整原始日志**：`<LOG>`。请定位首先出现的 FATAL/ERROR，区分报错发生于环境检查、BD Tcl 导出、模块引用、IP Catalog、综合、实现、时序或 XSA 阶段。优先给最小修复，不要删除已通过测试的原工程，也不要通过 `catch` 吞掉真实错误。提供修复前后差异和回归步骤。

## Prompt C：独立验收

根据**新重建工程**的综合完成状态、Implementation 状态、WNS/WHS、`check_timing.rpt`、`drc.rpt`、Bitstream/XSA 文件以及 Vitis/板级日志，生成验收矩阵。请分别给出 BD 级、工具实现级、板级功能级通过/待验证/失败，不要把某一阶段通过当成所有阶段通过；注明工具版本、器件型号、输入数据规模和无法判断的项。

## 必须人工核对

- AI 不可代替实际运行 Vivado/Vitis；不要采信没有原始日志支持的 PASS。
- IP Repo、PS GEM/MIO、PLL/时钟、AXI DMA 通道、寄存器地址与缓存维护必须同真实工程一致。
- 修改设计 Tcl、XDC 或 RTL 后，应重新考虑此前实现和板级证据是否仍适用。
