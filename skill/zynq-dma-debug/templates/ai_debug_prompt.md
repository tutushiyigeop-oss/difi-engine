# 大模型协作提示词：证据驱动的 AXI DMA 排障

> 将以下模板按实际项目填写后提交给 AI 助手。不要提供隐私凭据或无关工程文件。AI 只能提出诊断假设；最终必须由真实硬件测试和日志证明。

```text
你是一名熟悉 Zynq-7000 / Vivado / Vitis Standalone / AXI DMA Simple Mode 的 FPGA 工程调试助手。
请只基于我提供的证据分析，禁止凭空补足未提供的连线、地址、时钟或测试结论。

硬件：芯片型号=...；Vivado/Vitis 版本=...；新/旧 XSA=...
AXI DMA IP：Simple/SG=...；MM2S/S2MM 是否启用=...；DRE=...；
地址/宽度/长度位宽=...；AXI4-Stream TDATA/TKEEP/TLAST/TREADY 连线=...
BD 数据流：...
BSP/应用：Standalone/Linux=...；轮询/中断=...；SDT/legacy=...
缓冲区：TX 地址=... RX 地址=... 大小=... 对齐=...
缓存操作：Flush/Invalidate 的具体位置=...
启动顺序：...
现象：MM2S Busy=...、S2MM Busy=...、错误寄存器 MM2S_DMASR=... S2MM_DMASR=...
日志与源代码摘录：...

输出要求：
1. 先判断可确认的事实和缺失信息，不准把猜测写为结论；
2. 按“最小代价排查”顺序列出最多 5 个原因，标明对应证据；
3. 每个原因给出一个最小验证动作、预期信号/日志与否证条件；
4. 优先核对 TLAST、传输字节数、DMA 初始化和 Cache；
5. 提供仅修改必要代码的补丁建议，指出是否需要重建 Bitstream/XSA/BSP；
6. 给出可复现的 PASS/FAIL 验收条件，并记录最终验证结论为待测。
```

## 纠错记录要求

至少保存首版 AI 建议、对应实际输出、失败证据、修正后的代码差异、复测结果和最终原因。没有实际发生的错误只能写成**假设场景/故障注入**，不能伪装为项目研发史。
