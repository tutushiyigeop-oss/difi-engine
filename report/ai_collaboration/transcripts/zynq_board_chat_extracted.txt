一、AXI DMA 这一页如何设置？

   你截图中的配置可以直接使用
核对如下参数即可：


配置项                                                                         应设置为

Enable Scatter Gather Engine                                                不勾选

Enable Micro DMA                                                            不勾选

Width of Buffer Length Register                                             14 bits

Address Width                                                               32 bits

Enable Read Channel                                                         勾选

Enable Write Channel                                                        勾选

Memory Map Data Width                                                       32 bits

Stream Data Width                                                           32 bits

Max Burst Size                                                              16

这里解释三个比较重要的参数。

1. Width of Buffer Length Register = 14

它决定了 DMA 单次传输长度寄存器能够表示的最大字节数。

14 bits 允许最大设置 16383 Bytes，而我们第一轮测试：

    MM2S：1024 Bytes
    S2MM：1052 Bytes

所以完全足够，不必改成 23 或 26 bits。

2. Memory Map Data Width 和 Stream Data Width

二者都设为 32 bits。

因为我们 DIFI RTL 的 IQ 输入与 Packet 输出都采用 32-bit AXI4-Stream，每个时钟周期传送一个 32-bit Word。

3. Allow Unaligned Transfers 不勾选

我们暂时不需要 DRE（Data Realignment Engine）。Vitis 后续分配和使用的 DMA 缓冲区地址确保至少 4-byte 对齐即可。

因此，这一页你可以直接点击右下角的 OK。

四、FIFO 到底什么时候做？
我不建议现在立即编写一个通用 FIFO 模块，然后在每条 AXI4-Stream 通路上随意插入。

应该根据数据来源决定。

场景                                                    FIFO 必要程度                                  我的建议

PS AXI DMA → TX IQ                                    非必需                                        当前能够正确背压，先保留直连

TX Engine → PS DMA / 网络                               根据缓冲及软件调度需要                                连续传输时再评估
<PARSED TEXT FOR PAGE: 56 / 56>
PS DMA / UDP → RX Engine                       根据突发接收情况需要       先保证完整 Packet 边界

实际 ADC → TX Engine                             通常非常重要           数据源不能停顿时需要弹性缓冲与溢出处

跨时钟域数据传输                                       需要 CDC 机制        优先使用合适的异步 FIFO


需要特别注意的是，FIFO 不能凭空解决持续速率不匹配。如果输入长期快于输出，再大的有限 FIFO 最终也会满。

而且对于真实 ADC 输入，FIFO 会增加采集到打包之间的延迟。若时间戳要求表示第一个 IQ 样本的实际采集时刻，还必须考虑采集时间与
缓存数据的关联，不能简单地拿 FIFO 出口时的时间代替采样时间。

所以 B5 应当先测量连续流的表现，再决定是否增加 AXI4-Stream Data FIFO、其深度及位置。如果仅仅用于短期缓冲，优先考虑 Vivado
自带的 AXI4-Stream FIFO IP，没有必要重新实现通用存储 FIFO。
