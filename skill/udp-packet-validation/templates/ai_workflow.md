# AI 协助 FPGA UDP 数据通路排障工作流模板

> 使用说明：将尖括号替换为真实信息，提供硬件接线图、PS lwIP 片段、抓包和失败日志。输出作为诊断建议，必须经独立工具/实验验证。

## 提示词一：明确验证边界

> 我正在验证 FPGA `<PART>`、Vivado/Vitis `<VERSION>`，结构是 `<PL AXIS IP → DMA → PS lwIP → PC>`。板卡 IP `<BOARD_IP>`，PC IP `<PC_IP>`，UDP 端口 `<PORT>`。协议包头/字段定义为 `<SPEC>`，预计 `<N>` 包，每包 `<LEN>` 字节，字节序 `<ENDIAN>`。请先判断哪些测量是 PL 内部、哪些是 PC 端观察结果；列出必须检查的网络和 DMA 前提，禁止把 UDP 发送函数返回成功认定为 PC 收到。

## 提示词二：定位实际问题

> 下面是发送端 UART、接收脚本输出和 Wireshark 抓包：`<EVIDENCE>`。请将**已观测事实**和**猜测原因**分开；按照证据权重逐层给出最小检查（IP/网卡/ARP → UDP 绑定/控制触发 → 数据长度/字节序 → IQ 参考模型 → PL 输出）。每项给出“若观察 A 则排除什么、若观察 B 则做什么”，不要直接修改所有模块。

## 提示词三：导出验证结果

> 根据以下真实抓包信息 `<PCAP>`、Profile `<CONFIG>`、第三方工具日志 `<LOG>`，填写 `templates/acceptance_report.md`。分开标注：离线 Profile PASS、真实 PC 网络接收 PASS、第三方工具 PASS、正式认证是否获得、吞吐率是否按去掉人为 pacing 的条件测量。若证据缺失必须写待验证。

## 对 AI 回答的纠错标准

- 所有字段需回查实际 RTL、协议规范或工具输出，不可从截图推测缺失的 Byte。
- 对没有真实数据支撑的“分片、时序、丢包原因”写出验证动作，不冒称已定位。
- 若需要脚本写入文件，先将原始 PCAP 只读保存，再对副本实验。
- 输出含可运行命令、期望结果、失败分支和已知失效条件。
