# 大模型协作与纠错证据库（DIFI 1.1）

> 整理版本：v0.1，2026-10-22。当前是**证据索引 + 技术复盘初稿**，不是完整原始对话备份。AMD 指南要求提示词、模型回答与纠错轨迹；原始对话不足的案例还不能标注“全证据闭环”。

## 仓库使用方法

1. 先阅读 [`ai_collaboration_report.md`](../competition/ai_collaboration_report.md) 了解整体协作方法与五个典型案例。
2. 对照 `evidence_index.csv` 核查所列 Git Commit、RTL、报告、原始日志的位置。
3. 将**原始聊天记录**按 `templates/conversation_record_template.md` 的说明保存到 `raw/`。建议每个案例按日期或聊天会话分文件，并引用原始会话截图或平台正式导出，保留角色和时间。
4. 更新各案例中的 `[待补]`，不要把事后复述、AI 根据结果推测的答案标成逐字对话。
5. AI 输出仅是建议；**只有实际综合/仿真/上板、日志与脚本版本匹配时，才升级验证状态**。完整验收时执行 `python report/ai_collaboration/check_evidence.py --repo-root .`。

## 证据等级定义

| 等级 | 可证明事项 | 示例 |
|---|---|---|
| E1 原始对话 | 谁在什么时候问了什么、模型逐字如何回答、如何纠正 | 带时间戳的原始文本导出、截图、用户上传的完整会话 |
| E2 工程提交 | 哪些源码/脚本发生改变、文件在何时进入 Git 历史 | Git Commit + Diff |
| E3 实验结果 | 在限定环境下获得什么综合、仿真、板级结论 | 原始 Vivado `.rpt`、UART、PCAP、官方工具日志 |
| E4 复盘说明 | 对已有过程的归纳、原因分析与经验提炼 | 本目录 `cases/*.md`；**不能替代 E1** |

注意：Git Commit 时间用于定位工程修订，不保证与 AI 聊天的时间一一对应。E2/E3 并不能自动证明这些修改由 AI 完成，也不能单独证明 AI 建议造成某项优化。

## 隐私、完整性与研究诚信

- 原始对话导出前检查是否包含账号、Token、个人信息或机器用户名；如需脱敏，应在副本中遮盖且记录脱敏范围，勿擅自改写技术结论。
- 不复制整个第三方 DIFI 验证器到本库，引用仓库对应结果及上游项目即可。
- 不将“通过一次 22 包测试”写成“协议完全覆盖”或“官方认证”；不将“开发者确认板级重建通过”直接写成已经提交新版 XSA 全套 UART 证据。
- 不将 4 个 Skill 的工具离线自检推断为它们已经完成跨项目、跨板卡实测；按既定计划最终统一验收。
